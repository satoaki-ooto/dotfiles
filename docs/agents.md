# コーディングエージェントの設定

各エージェントの設定は `agents/<agent>/` に置き、`[dotfiles]` で deploy する。
`AGENTS.md` と `rules/` は「全エージェントで共通」という位置づけなので `agents/shared/` に
1 箇所だけ置き、各エージェントから参照する。
エージェント自身が書き換えるファイルは `merge` で「自分のキー」だけ管理し、
そうでないものは `copy`（実ファイル）にする。symlink だと sandbox 内で
`~/.config/mise` が見えず設定を読めないため。

- [pi](pi.md)（`agents/pi/` → `~/.pi/agent/`）
- [pig](pig.md)（`agents/pig/` → OS ごとの root。macOS: `~/.pig/agent`、Linux: `~/.config/pig/agent`）
- [omp](omp.md)（`agents/omp/` → `~/.omp/agent/`）
- [octet](octet.md)（`agents/shared/` → `~/.octet/`）
- [kilo](kilo.md)（`agents/kilo/` → `~/.config/kilo/kilo.jsonc`）
- [ags](ags.md)（`agents/ags/` → `~/.config/ags/`）

## `agents/shared/` に何を置くか

`agents/shared/` は、このリポジトリで管理する全エージェントに常時効く振る舞いだけを置く場所。
育て方は「最初から揃えず、必要になったら上げる」。

### 置き場所の判断

| 内容 | 置き場所 |
|---|---|
| このリポジトリで管理する全エージェントに、どのプロジェクトでも常時効く振る舞い | `agents/shared/`（`AGENTS.md` / `rules/`） |
| 特定のエージェントの都合（設定の形式、固有の機能） | `agents/<agent>/` |
| 特定のリポジトリの規約（言語、フレームワーク、ドメインの語彙） | そのリポジトリの `AGENTS.md` / `CLAUDE.md` |
| 特定の作業の手順（常時読む必要はない） | Skill（別に管理） |
| 機械的に止められる逸脱（main への push など） | ルールではなく柵（extensions など） |

### shared に入れる条件

次のすべてを満たすものだけ入れる。

1. 実際の失敗か、繰り返した手戻りに対応している。一般論や思いつきは入れない。
2. 責任範囲は、このリポジトリで管理しているエージェントのみ。対象は `agents/` に置かれ `[dotfiles]` で配られるもので決まり、増えれば自動で範囲に入る。リポジトリの外で管理されるエージェントに合わせるための変更はしない。その範囲の中では、特定のエージェントの実装や癖に依存せず、どのエージェントに配っても同じ意味で効く形で書く。
3. 守れているかを後から確認できる。確認できない精神論は、確認できる形に直してから入れる。
4. プロジェクト側の規約と衝突しない。衝突する場合はプロジェクト側が勝ち、shared は補完に留まる（`agents/shared/AGENTS.md` の位置づけどおり）。
5. 根拠を一緒に書ける。そのルールが何を守るのか（読む人間か、保守の経済か、安全か、現行モデルの挙動か）を明示する。根拠の置き場で、ルールの寿命が決まる（運用を参照）。

個別のエージェントで必要になったルールは、まず `agents/<agent>/` 側かプロジェクト側に置く。
2つ目以降のエージェントでも同じ内容が必要になった時点で、shared に上げる。
shared が生まれた経緯（pi と pig で同一だった内容の集約）と同じ上げ方にする。

### 運用

- 追加は最小の行から。逸脱や手戻りが出たら、その分だけ足す。
- 機械的に止められる逸脱は、ルールではなく柵で止める。ルールは確率的にしか効かないため。
- 狙いは不変。根拠が読む人間・保守の経済・安全にあるルールは、モデルの世代が変わっても残す。棚卸しの対象にしない。
- 根拠が現行モデルの挙動にあるルールは「暫定」と分かるようにしておく。モデルの世代が変わったら見直すのは、暫定のものだけ。
- 不変かどうかの判定には、次の2つを使う。新入りの人間にもそのまま言えるか。LLM 以前のソフトウェア工学に出典があるか。両方に当てはまれば不変側に置く。
- shared の変更は配布先の全エージェントに効く。変更時は波及範囲を意識する（`REVIEW.md` の扱いどおり）。
- 配布先を増やすときは、`agents/<agent>/` にそのエージェントの設定を作り、shared は共通の土台としてそのまま配る。エージェントごとに設定が違うのは当然で、差異は `agents/<agent>/` 側で持つ。shared 側の変更が必要に見えたら、入れる条件を満たすか（リポジトリ内の全エージェントに同じ意味で効くか）で判断し、満たさないものはエージェント側に置く。
